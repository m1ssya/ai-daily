# Code Standards

本仓库主要是一份 Node.js 静态生成脚本、一份站点 CSS，以及期次 JSON。跨语言的通用原则仍然适用；不要为了「完整性」引入本项目没有的服务端或框架约定。

- 优先清晰、可维护的实现，避免隐式副作用和不必要抽象。保持无框架、无运行时依赖的现状，除非有明确理由并留下 ADR。
- 构建失败必须抛出明确错误；不要吞掉 JSON 解析或校验失败。
- 对期次 JSON 做输入校验；渲染到 HTML 时转义用户可见字段。`post_url` 只接受构建脚本允许的 `x.com` 状态链接格式。
- 不要在代码、文档或示例中写入密钥、Token 或生产凭证。当前构建不需要这类配置。
- 用户可见文案使用简体中文。只收录真实原帖，不编造链接、用户名或数字。
- 公共页面路径、期次字段或校验规则变化时，更新根目录 README、相关 Subsystem 文档，并评估 Changelog。

新增依赖前说明必要性、维护状态、许可证、供应链风险和替代方案。目前 [`package.json`](../package.json) 没有第三方依赖。

## Review checklist
- 是否引入不必要复杂度或依赖？
- 期次校验、HTML 转义和错误信息是否仍然有效？
- 是否存在秘密泄露或未转义的 HTML？
- `npm run build` 是否通过？文档是否覆盖行为变化？
- 是否误把 `out/` 或截图提交进仓库？
